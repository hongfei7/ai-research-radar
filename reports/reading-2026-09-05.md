## 1. [Anthropic says Claude worked "largely autonomously" over 11 days to formalize the proof of Fermat's Last Theorem in the Lean programming language (Anthropic)](https://www.techmeme.com/260904/p28#a260904p28)

*一手研究解读 · rss:techmeme · 2026-09-04 · 可溯源一手材料*

**主张** 这是 Anthropic 官方通稿的 Techmeme 聚合：声称 Claude 用 11 天基本自主地在 Lean 中形式化了费马大定理的完整机器可验证证明。正文仅一句公告,无技术细节。

**证据** 唯一可引用的具体陈述是 Anthropic 自述的三个关键词：'11 天'时长、'largely autonomously'、'first complete computer-checked proof' 的定性说法。无 Lean 代码规模、无人为干预次数、无对照基线。

**薄弱处** 几乎所有关键信息缺失：形式化起点是 Wiles 原文还是已有 mathlib 片段？11 天是人机循环总时长还是纯模型运行？'largely autonomous' 如何量化？与 LeanDojo、DeepSeek-Prover、Aristotle 等系统的对比如何？Anthropic 作为模型厂商有强烈商业动机，且该声明未经第三方独立复现，本条本身就是利益相关方口径。

**冲突点** 与社区既有认知严重冲突：费马大定理的完整 Lean 形式化此前被视为长期未竟工作，若 '11 天基本自主' 属实将颠覆对自动形式化难度的普遍估计；但无技术报告佐证，更接近营销叙事而非可复现科研进展。

**延伸** 追踪 Anthropic 同期是否放出技术报告或 Lean 仓库，重点核对 agent 循环架构、人为纠错频次、形式化起点；并对照 Kevin Buzzard 等社区形式化工作及 DeepMind Aristotle 项目的进展判断增量。

## 3. [Clean Engineering, Unstable Measurement: A Preregistered Reliability Failure of Black-Box LLM Observers on Shared Endpoints [Haoyaun Zhu, Jie Zhang]](http://arxiv.org/abs/2609.04198v1)

*一手研究解读 · arxiv:cs.AI · 2026-09-03 · 可溯源一手材料*

**主张** 共享 LLM 端点作为评测"裁判"不具备可复现性：同一模型名、同一请求、同一字节输入，次日排序仍显著漂移，问题出在测量端而非工程端。

**证据** 52,988 次请求审计；同窗口重排 Spearman 0.400（要求 0.90）；次日字节一致重放 0.78（要求 0.99）；执行日志全达标；四家供应商中位数 0.74–0.88；等五天无改善（0.805 vs 0.800）；自托管批不变内核仅在低负载时有效；构造错误实验显示读数分离度跟错误类型走而非大小。

**薄弱处** 仅依据摘要判断：未披露受测模型、任务与供应商名单；失败由限流、负载均衡、量化还是供应商侧 A/B 路由造成未说明；专用 API 端点是否同样失效证据单薄，仅"自托管低负载有效"未覆盖独立租户；摘要未提利益冲突。

**冲突点** 与主流 LLM 评测共识直接冲突——排行榜、RLHF/DPO 数据过滤普遍默认"模型名+版本号=可复现仪器"；作者主张该假设基本不成立，且元数据字段无法预测哪个供应商更稳。

**延伸** 读 PDF 确认受测模型/供应商清单与采样设计；交叉参考 batch-invariant kernel 原始论文（vLLM 团队相关工作）以判断自托管路径的可推广性；查 Chatbot Arena、AlpacaEval 是否披露过类似 jitter 测试。

## 4. [Why Gated DeltaNet Survives 4-Bit Quantization: NVFP4 W4A4 for the Recurrent Half of a Hybrid 27B LLM [Sergii Kozyrev, Davyd Maiboroda]](http://arxiv.org/abs/2609.04098v1)

*工程实践与复现 · arxiv:cs.AI · 2026-09-03 · 可溯源一手材料*

**主张** Gated DeltaNet 其实是混合 LLM 中'容易量化'的那一半; 在 Qwen3-27B 上做 NVFP4 W4A4 全量化, 性能与 BF16 仅落在 seed 噪声内, 而且模型更小、prefill 更快。

**证据** 496 个 linear layer 全部 NVFP4, 5-task 平均 -0.52, 模型 17.5 GiB, prefill +14-19%; 评测覆盖 4K/32K PPL、MMLU-Pro、GSM8K、AIME'25、GPQA-Diamond、LiveCodeBench、RULER-64K; gate 投影将 ~11% GEMM 误差压到 ~2% 输出误差; delta-rule 噪声在 32K 内保持平台。

**薄弱处** 仅依据摘要判断, 未见 attention half 的对照分析, 也未与 MXFP4/GPTQ 等 4-bit 方案头对头; AIME'25、GPQA 等具体分数未列; 修复 fused-GEMM 尺度不匹配的具体收益未给; 16 个 attention layer 是否同样走 NVFP4 不明确; checkpoint 出自作者本人, 缺独立复现。

**冲突点** 与社区主流直觉冲突: 此前普遍担心 GDN 的 decay 与 write-strength gate 在 4-bit 下会因误差累积而崩塌, 作者却证明 gate 反而最不敏感、循环噪声在 32K 内不放大; 即与'长上下文循环状态对量化脆弱'的常识正相反, 增量在于给出机制级解释。

**延伸** 读原论文 mechanism 四部分消融细节, 对照 Qwen3-27B 技术报告与早期 GDN 8/16-bit 量化基线, 再核 NVFP4 硬件规范 (Blackwell/GB200), 并顺藤摸 Gated DeltaNet / delta-rule 收敛性相关文献。

## 5. [Hardware-Aware FP4 FlashAttention-4 [Robert Hu]](http://arxiv.org/abs/2609.04105v1)

*工程实践与复现 · arxiv:cs.LG · 2026-09-03 · 可溯源一手材料*

**主张** Blackwell FP4 tensor core 不会自动加速 attention,因 softmax 转换与片上依赖成为主导瓶颈;论文提出 Direct-P 将 score 直接映射为 FP4 概率用于非因果推理,以及一条把前向量化结果传入反传的 causal 训练路径。

**证据** NVIDIA GB200 上 Direct-P 非因果前向达 BF16 的 2.13×;causal 路径配合 FP8 梯度算子,单卡 8B 参数完整 update 加速 1.14×;分布式训练中所有 MXFP4 概率/值组合的轨迹全部发散,只有 FP8 概率+值训练保持稳定。

**薄弱处** 仅一作 Robert Hu,摘要未给出与 FA3 等近期实现的对比;8B 模型 1.14× 加速缺乏 perplexity/下游指标佐证;MXFP4 发散的具体触发条件(精度格式、batch、步数、是否单步还是稳态)未交代;2026 年 GB200 可复现性受限于硬件供给。

**冲突点** 与"降精度即提速"的主流直觉相左,作者把瓶颈从 GEMM 拉回到 softmax 与片上依赖,且报告 MXFP4 概率/值训练全发散这一新失败模式;和近年低精度训练可行性的乐观叙事直接冲突。

**延伸** 读全文弄清 Direct-P 的具体公式与 softmax 瓶颈分析;对比 FlashAttention-3 论文与 GB2026 Blackwell 架构资料;查"score 直接量化为概率"是否已有先验工作;关注 MXFP4 发散的根因——
